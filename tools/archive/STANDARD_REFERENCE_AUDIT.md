# 标准：引用审计

Last updated: 2026-10-10

状态：**标准（normative）**。用于"移动前判定"与"批次验收"。

## 1. 目的

在移动任何目录/文件前，确认它**是否被引用**；移动后确认**旧路径引用已归零**。

## 2. 审计范围（语料）

`docs/**`（含 `legacy/`）、`config/**`、`components/**`、`application/**`、`middleware/**`、
`linker/**`、`.githooks/**`、`CMakeLists.txt`、`AGENTS.md`、`tools/tool_registry.json`、
`tools/tool_layout.json`、`tools/README.md`。

**排除**：`out/**`（产物）、被审计对象自身目录、`tools/archive/**`（归档记录）。

## 3. 方法

- 对每个待审计条目，取其**目录/文件名**在 §2 语料中做**子串匹配**（覆盖字符串拼接与动态 import）。
- 记录命中次数与样例路径（前 2 条），用于判断"强引用"（门禁/凭证/构建）还是"弱引用"（历史叙述）。
- 输出两份：
  - 机器可读 `tools/_ref_audit.json`：`{ "referenced": [...], "unreferenced": [...] }`
  - 人读 `tools/archive/REFERENCE_AUDIT.md`：方法与结论表 + **旧路径 → 新路径映射**。

## 4. 判据

| 场景 | 判据 |
|---|---|
| 移动前 | 若"强引用"命中 ⇒ 必须同批更新引用，或**放弃移动**（原位保留） |
| 批次验收 | 旧路径引用数 = **0**（兼容 wrapper 的自身引用除外） |
| 全量完成 | `_ref_audit.json` 中不再出现旧顶层路径；域目录成为唯一引用目标 |

## 5. 复审计触发条件

① 每次迁移批次结束时；② 新增/改名/移动工具目录后；③ `docs/**` 大批改动后；
④ 用户要求时。复审计结果追加到 `REFERENCE_AUDIT.md`（保留历史，不覆盖）。

## 6. 记录格式（REFERENCE_AUDIT.md 追加节）

```text
### <批次号> <日期>
- 范围：<被移动目录清单>
- 引用更新：<文件:行 → 新路径>（可按文件聚合）
- 审计结果：旧路径引用 = <N>（目标 0）；例外与理由：<...>
- 抽样验证：<命令 + 结果>
- 回滚路径：<git mv 反向命令或提交回退>
```
