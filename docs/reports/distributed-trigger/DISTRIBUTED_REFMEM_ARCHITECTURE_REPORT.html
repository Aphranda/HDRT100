Distributed RefMem ArchitectureA0-A7 Slots And 9 Tables
逻辑槽位与静态模型：节点可加载到任意 A0-A7，表必须整体激活
A0-A7 是全环唯一逻辑 slot substrate；BoardCapability 是多板能力资源综合表；节点实例由 NodeLoad 绑定到 slot。
A0-A7 逻辑 slot 语义
对象含义上限/容量
A0-A7全环 8 个可装载逻辑 slot，不固定产品角色。active slot count = 8
同板多实例一块板可加载模拟网分和模拟转台等多个实例。candidate proposal max = 16
NodeRegion[8]只保存 A0-A7 心跳和装载摘要，不是新 slot 空间。8 × 512 B = 4 KB
SlotClaimMap协调 physical board 到 logical slot 的 active assignment。overflow 必须进入 evidence

同步闭环：RefMem 是 core0 状态机，TDMA/PIO 是最小真实物理链路
首版最小系统板优先用 PIO SPI 承载 DELTA/ACK/FENCE/QUALITY；后续 BISS-C/RJ45/UART 都作为 transport adapter 接入同一协议。

Distributed RefMem ArchitectureOwner / Guard / Quality
表驱动隔离：owner、sequence、CRC、seqlock/guard 都是 region 契约元素
向量表不承载大数据，但承载保护事实；它解决“谁能写、何时有效、读到的是不是一致快照”的问题。
唯一 Writer
DataLink 声明 region_path、writer_instance、reader_mask 和 permission。多 writer 是 DeploymentGate 的拒绝项，不允许用 SCPI 临时绕过。
Guard / Seqlock
region guard 至少包含 seq、owner、writer、crc、stale、write_epoch、write_tick。跨核共享区仍要用 owner、sequence、CRC 或 seqlock。
Flash Lockout
core1 关键入口必须 RAM-resident，flash erase/program 前必须 park/lockout，并把请求、ACK、release、timeout 写入 header 保护摘要。

契约项来源表/region工程作用

冲突类型不能只靠向量表解决的原因当前架构处理方式
双核同时访问 RAM 结构不同 core 可能读到半更新字段。owner + sequence + CRC + seqlock/双缓冲，reader 发现 seq 变化则重读。
core0 flash erase/programcore1 从 XIP flash 取指会被阻塞或出错。RAM-resident section、flash lockout/park、entry table owner 归属写入 Header。
两个节点 claim 同一 A slotVector region 固定，不等于可分配 slot。SlotClaimMap 协调，冲突进入 evidence；超出 8 active 或 16 candidate 直接拒绝。

当前审核结论
问题当前结论后续审核重点
Vector 16 槽是什么固定 region directory，不是可替换节点槽位。所有文档/代码继续避免把 region 和 logical slot 混用。
BoardCapabilityTable 是否每节点一份不是；它是系统级多板能力资源综合表。加载时可改单条 draft，但 active 必须整体 package。
一块板加载 9 个节点是否可验证可作为反向验证 candidate，但 active slot 仍只有 8，candidate 上限 16。overflow 和冲突必须走 SlotClaim evidence。
RefMem 是否偏离 HAOFV当前已回到 AO/FB owner + 表驱动 + snapshot 边界。禁止新增绕过 owner 的 SCPI direct write。
下一步建议：先完成 P0 硬件闭环，再继续扩展字段级 region contract 和自组网协调。
