项目定位：DHRT100 是基于 RP2350 的分布式硬实时触发平台，目标是在多板节点之间形成共同事实、共同时间、确定性传输、预约分发和实际 T2 回读闭环。当前架构主线已从单板功能堆叠收敛到 HAOFV：Active Object 管运行，Function Block 管状态机，Vector/RefMem 管事实，TDMA 管传输，Calibration 管链路测量，VDC/DPLL 管共同时间。
当前结论：RefMem、TDMA、VDC、Calibration 均已建立独立主域和关键代码基础件；四板校准 P3 已形成诊断级四时间戳证据，但 endpoint bias、freshness、active/staging gate 和 VDC/DPLL 正式消费仍未完成。

三、HAOFV 分层模型
SCPI / UI / SD / Bootloader Result -> Active Object Layer -> IEC 61499-style Function Block Layer -> Time-Synchronized Vector Blackboard Layer -> Virtual Distributed Clock / VDC Domain -> Calibration Domain -> Distributed Vector Blackboard / RefMem Sync Domain -> TDMA Foundation Domain -> Hardware Service Layer Hard Realtime Side Path: PIO / DMA / IRQ
四、架构核心规则
规则工程含义当前落点
唯一 owner每个事实、状态机和硬件资源必须有唯一 writer；外部入口只提交 intent 或读取 snapshot。AO/FB/Vector、TDMA owner、VDC owner。
跨核事实保护core0/core1 共享多字段事实必须使用 seqlock、双缓冲或等价 sequence/version，并用 acquire/release 语义发布。RefMem command、TDMA runtime、flight FIFO。
硬实时旁路PIO/DMA/IRQ 只执行边沿、搬运、deadline 和最小 evidence；不能访问 USB、SD、SCPI 或复杂业务解析。core1 realtime loop、TDMA PIO persona、sync_io。
共同事实与共同时间分离RefMem 保存多节点共同事实；VDC 保存共同时间映射；二者互相引用但不得互相代写。RefMem VdcSlot、VDC snapshot、DeploymentGate。
诊断证据不能升级软件 timestamp、host 脚本耗时、单板 reference loopback 都不能冒充 active calibration 或 DPLL eligible evidence。DIAGNOSTIC_ONLY / REFERENCE_LOOPBACK flags。

十一、VDC/DPLL 技术路线
对象技术路线状态
local_tick_raw每块板自由运行、单调递增的原始硬件 tick；硬件 latch 锁存原始 tick，DPLL 不修改原始计数器。基础成立
VdcMapSnapshotVDC 维护 local_tick_raw 到 vdc_time 的仿射映射：anchor、offset、rate、phase slew、epoch、quality 和 generation。首版完成
SyncDpllFB借鉴 LinuxPTP/Chrony servo：相位误差、频率误差、Kp/Ki、outlier、jitter、RMS、holdover 和 reset 策略。待长稳
EtherCAT DC 思想借鉴 reference clock、propagation delay、initial sync、drift compensation 和同步输出/输入 timestamp；不采用 EtherCAT 协议。已纳入
DCO SnapshotDPLL 输出给 core1 的只读 snapshot，供 future FIRE_LOAD 和相位牵引消费；core1 不写 offset/rate。待接入
十二、timestamp latch 与 VDC 的关系
关键结论：硬件 timestamp latch 不需要先有 VDC。它只锁存原始 local_tick_raw，因此系统启动时可以先用固定本地 tick 采集同步边沿；随后 DPLL 根据这些原始样本和校准 delay 形成 VDC 映射。VDC 锁定后，PIO 预约执行不直接读取软件 system_tick，而是由 core1 使用 VDC 的 local_from_vdc() 把未来共同时间反算为本地硬件 deadline。
接口用途门禁
vdc_from_local()把 T2_actual_local、SYNC/READY latch 等原始硬件 tick 映射回共同时间。必须绑定 map_generation 和 mapping quality。
local_from_vdc()把未来 T_fire_target_vdc 反算为本地 PIO deadline。必须使用稳定 VdcMapSnapshot，guard 前 generation 变化需重算。
system_tick可以作为 VDC API 的只读封装，包含 offset/rate/slew。不能只是 local + fixed offset，也不能替代硬件 latch。
十三、T2 预约端到端流水线
raw local clock + hardware edge latch -> TDMA clock-training observation -> VDC DPLL offset/rate mapping -> Trigger future reservation in VDC time -> TDMA flight distribution + READY/fence -> VDC target-to-local inverse mapping -> sync_io / PIO executes local deadline -> hardware latches actual edge as raw local tick -> VDC maps completion back to common time -> RefMem/TDMA publishes completion evidence
十四、VDC 当前缺口
  • active calibration CRC、link delay 和 freshness 尚未完全接入正式 VDC lock gate。
  • 常驻 TDMA observation / idle beacon 仍需由固件内部连续运行，不能依赖 host 重装窗口。
  • 100 ns fine tier 需要稳定硬件 timestamp evidence、BAD_FRAME/WINDOW_BOUND 收敛和长时间验证。
  • core1 稳定读取 DCO snapshot 并驱动 FIRE_LOAD / sync output 的路径仍需验证。
十五、T2 当前缺口
  • TriggerReservationFB 的精确 wire layout 和 System Pack segment 仍未冻结。
  • READY/NACK、fence、completion 的丢帧策略和 retry/fail-closed 需要 HIL。
  • T2_actual_local 必须来自硬件 latch，不能由 CPU 查询或软件完成时刻填充。
  • 1/2/3/5/8 节点逐级验证尚未完成。
VDC/DPLL 的正确方向是“原始 tick 先可测、VDC 映射后可用、预约用反向映射、完成用正向映射”。

十七、双向同时对比法
对链路 A -> B: t1 = A.CLK_TX A 本地时钟：CLK 正向发送 t2 = B.CLK_RX B 本地时钟：CLK 正向接收 t3 = B.DATA_TX B 本地时钟：DATA 反向发送 t4 = A.DATA_RX A 本地时钟：DATA 反向接收 residence_B = t3 - t2 path_sum_AB = (t4 - t1) - residence_B delay_A_to_B ~= path_sum_AB / 2 # 仅在对称性门禁通过时成立
门禁要求状态
四边沿 latcht1..t4 必须来自同一 epoch、同一 PIO persona 的 hardware-latched edge，CPU timer 不能替代。诊断具备
endpoint bias必须用同 persona 的板内 reference loopback 生成 bias generation，未生成时只能发布 observed value。关键缺口
对称性等长差分线缆支持对称假设，但需通过重复统计、asymmetry bound 和四板 residual 检验。待冻结
active 发布需同时通过 hardware latch、bias、freshness、topology/profile CRC、重复统计和故障注入。未发布

十九、主要风险
时间戳风险：若没有真实硬件 latch 和非 diagnostic flags，VDC/DPLL 不能进入正式 100 ns lock gate。
校准风险：缺少 endpoint bias 会让 observed delay 无法升级为 per-link active delay。
可靠性风险：TDMA/RefMem 仍需 ACK/重发/fence 和长稳验证，不能以单次 HIL 通过替代产品门禁。
