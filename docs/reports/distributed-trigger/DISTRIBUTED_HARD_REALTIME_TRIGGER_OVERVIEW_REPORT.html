Distributed Hard Real-Time Trigger SystemArchitecture Overview
总体架构：共同事实 + 共同时间 + 硬实时执行
当前框架已经从单板触发控制，收敛为可扩展的分布式硬实时系统平台
HAOFV 主线
Active Object 管生命周期和事件入口；Function Block 管状态迁移；Vector 管事实、版本和唯一 writer；Service/PIO 只执行受限底层动作。
Distributed RefMem
64 KB Distributed Vector Blackboard 维护共同事实：slot、ACK/NACK、stale、CRC、TableRegistry、RMA Window、静态 AO/FB 图和部署门禁。
Virtual DC
VDC Domain 维护共同时间：local_tick 到 vdc_time 映射、SYNC DPLL、HOLDOVER/RELOCK、servo profile、error budget 和时间质量。
核心分层
1
SCPI / UI
只表达配置、动作意图和查询
2
AO / FB
owner task 消费事件并推进状态机
3
RefMem / VDC
共同事实与共同时间形成 RUN gate
4
core1 / PIO
固定小载荷、指定 tick 输出或捕获
内部主域回答的问题关键输出边界
RefMem Domain多节点共同认知是什么VectorTable、slot snapshot、ACK/NACK、deployment gate、evidence不计算 VDC，不承载大文件/波形/OTA payload
VDC Domain多节点共同时间是什么offset/rate、vdc_time、lock quality、HOLDOVER、servo/error budget不执行业务触发，不直接操作 PIO
TRIG/Loop/Realtime什么时候、以什么动作输出sequence、T_fire_base、FIRE_LOAD、T2/READY timestamp只消费 VDC snapshot，不写 offset/rate
一句话：RefMem 管共同事实，VDC 管共同时间，PIO/core1 管硬实时边沿。

能力闭环：从业务意图到硬实时证据
系统的产品化关键不是单条指令，而是配置、时间、执行、证据在 RefMem 和 VDC 上形成闭环
运行闭环
闭环系统语义关键事实
配置闭环SCPI/UI 写入配置意图，AO/FB 校验后提交到 RefMem staging/active 表。version、owner、CRC、apply_seq、rollback_id
时间闭环SYNC 捕获时间戳，VDC DPLL 估计 offset/rate，并输出可消费的共同时间。local_tick、vdc_time、offset、rate、quality
动作闭环LoopEngine 根据序列和 VDC 计算目标时刻，core1/PIO 负责确定性输出。T_fire_base、FIRE_LOAD、late_flag、done_ack
证据闭环捕获 T2/READY、late、CRC、seq、stale 等证据，用于报告和故障恢复。timestamp、fault_latch、trace_id、snapshot_id

有限版本产品化门禁
门禁项必须成立的条件通过后的系统价值
最小四板环路A0-A3 节点在线、slot 心跳有效、SYNC_RING 捕获/回传闭合。证明系统不是单板触发器，而是分布式同步控制器。
校准到同步链路CAL 写入链路 delay，VDC 使用 delay 建立 offset/rate，SYNC 能读回质量。T2 预测分发具备数据基础，角度点内序列可按共同时间执行。
序列到边沿输出CONFigure:TRIGger / SEQuence 形成动作表，LoopEngine 生成 FIRE_LOAD，PIO 输出可捕获。链路控制节点、极化、频点、波位序列进入可验证的自动执行流程；当前项目实例具现为 SP8T/SP2T 等链路开关资源。
故障与恢复闭环late、stale、CRC、seq、HOLDOVER 超限能够锁存、读取、清除并重新 ARM。上位机可以完成运行判定、异常定位和恢复，不依赖人工猜测。
有限版本判断：优先证明四板同步环路、校准 delay、预测分发和故障恢复闭环。
