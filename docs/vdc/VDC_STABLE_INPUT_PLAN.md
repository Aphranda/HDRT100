## 1. 当前范围

DPLL/VDC 时间同步属于 TDMA 特等席负载，沿已有固定 process-image/trailer 和
优先预算准备、装载、卸载有效时间样本；不得降为普通日志或控制消息运输。
优先交付与消费校正分开：DPLL 只按实际有效样本更新，偶发坏帧不会阻塞飞行环路。

直接复用已经跑通的四板飞行数据通路。TDMA 启动首帧允许不可用，先预热传输，再从
当前运行代际的任意有效时间样本开始 DPLL；不要求首档可用、首序号固定、ordinal
为零或先取得连续无错的固定样本窗口。预热由板端运行状态及实际输入有效性判断，
主机等待时间不代表时间样本有效；若需要额外预热参数，在 STOP 配置、ARM 冻结。

首发与首档一一对应、启动时 PIO 路径精细采样、首原始窗口不跨 CS 的完整证明，
归入 `TDMA-REFINE-001/002/003` 后续优化。它们不阻塞 DPLL 后续工作，也不作为
`VDC-TIME-003/004` 的依赖。只有实测定位到某个 TDMA 缺陷破坏当前有效时间输入时，
才修复那个具体缺陷；不重新展开整套启动证明。

数据通路已有验收不等于指定主机数据接收或自主时间输入已经接通。先验证各从
收到 NO1 数据，再沿测量、反馈、命令、应用定位闭环缺口；不能由诊断档案推断锁相结果。

## 2. 有效样本驱动更新

下表是待实现并验收的处理目标。样本拒绝、控制锁定、质量新鲜度分别记录。

| 输入或事件 | 控制动作 | 记录与恢复 |
|---|---|---|
| 启动首帧或预热帧不可用 | 跳过该样本，尚未有有效输入时不开放校正。 | 保留失败原因；后续有效帧可以建立时间锚，不要求修复首档。 |
| 正常有效新样本 | 在 SyncDpllFB 确定性边界更新，使用当前有效时间关联。 | 保留本次与上次有效样本的时间、序号、代际及实际间隔。 |
| 偶发坏帧、缺帧、重复、陈旧输入或快照暂时读不到 | 本次不更新 PI/DCO；保持积分、可信频率值和有效时间锚，DCO 继续运行；不因这一帧直接清锁或重新捕获。 | 增加对应诊断计数，不刷新最后有效时间，不伪造有效样本。下一有效样本继续更新。 |
| 收到旧代际样本，但当前配置与时间基准未变 | 丢弃旧样本，保持当前环路。 | 区分“收到旧数据”和“当前时间基准实际换代”。 |
| 连续缺失达到按时间定义的保持边界 | 停止把过去的锁定状态当作当前精度保证，按保持误差预算进入 HOLDOVER 或重新捕获。 | 超时用当前时间减最后有效时间，不用 SCPI 查询次数或 service 次数；正式质量按年龄和误差预算判定。 |
| STOP/重新 ARM、实际源或时间模型换代 | 撤销不再适用的时间锚和待应用输入，按新代际重新捕获。 | 由 owner 确认实际配置变化；不让单份坏报文重置健康环路。 |
| 有效测量证实相位误差超出跟踪能力 | 按环路策略重新捕获。 | 依据真实误差与状态判据，不把 CRC 错误等同于相位误差。 |

例如有效样本之间隔过若干发帧周期，频率估计使用这两个有效时刻的真实差值。
积分更新也应明确时间步长、饱和和长间隔策略；不得把丢失期间假装成已经执行多次
有效校正，也不能简单将静态周期常数放大。首次有效样本建立锚，后续样本才提供
跨样本频率信息。序号按有界无符号差处理回绕、重复和过期，不要求每次 CPU 服务
看到物理序号恰好加一；较慢消费与硬件事件丢失分别计数。

偶发丢样本可能延长收敛或增加保持期间的不确定度，但不应直接触发失锁。
保持控制状态不代表永久保持正式精度资格；正常 quality aging 继续运行。

## 3. 可复用实现与实际差距

以下为源码与验证状态快照，非产品事实；初始审计见
`VDC-PROGRESS-20260915-049`，样本跳过切片及最新输入测量见
`VDC-PROGRESS-20260916-001`。

| 位置 | 已有基础 | 当前应处理的差距 |
|---|---|---|
| `components/tdma/src/tdma_pio_spi_phys_origin.inc`、`components/tdma/src/tdma_pio_spi_ring_origin.inc` | 自主循环、每圈记录与版本化序号；运行数据可流转。 | 自主接收仍给出零时间戳，启动清理 clock observation；原始记录不能直接冒充正式边沿时间。应补当前有效样本所需的最小时间生产与交接。 |
| `components/vdc_dpll_manager/src/vdc_dpll_manager.c` 的 `vdc_dpll_manager_ring_observer_service()` | 无输入、暂时不可用和重复输入已有有界返回；identity/path/expand/prepare/apply 有分层状态。 | 先读取实际输入及计数，确认哪个分支阻止本轮更新。不能把 P3 的 TDMA-only 结果当作 DPLL 已测量。 |
| `components/vdc_domain/src/vdc_domain.c` 的 `vdc_domain_reject_requires_reacquire()` 与 `vdc_domain_apply_prepared_tdma_evidence_state()` | 单样本拒绝跳过并保留积分/DCO/有效时间锚，已完成 host 与当前源码四板 P3 集成验证；本地无效 schedule 保持异常处理。 | 有效自主输入接通后验证实板坏样本恢复；单独 clock/path/dictionary 发布的真实换代清理与持续失效另行闭合。 |
| 同文件 `vdc_domain_update_clock_from_evidence()` | FLL 使用有效锚之间的 `expected_delta`。 | Ki 当前使用 `servo.update_period_us`；需独立核对实际有效间隔、单位和限幅。已有 FLL 锚可跨多个样本，不能直接将它当作 Ki 的上次更新时间。 |
| 同文件 `vdc_domain_service()` 及质量逻辑 | 已有年龄刷新、保持相关字段；从机缺命令保持输出。 | 尚未确认完整的超时进入 HOLDOVER 路径；不能写成已具备。先修单样本跳过，持续失效与恢复再独立验收。 |

继续使用已有 source/sequence/config/epoch、CRC、时间有效性和有界快照校验。

主板 TX 与接收侧的时间必须对应有效的发帧事件；这可以从稳定运行中的任意合格帧
建立，不要求从启动首帧逐圈追溯。诊断本地时间、映射后共同时间及正式精度资格分开。

## 4. 执行切片与退出条件

以下为时间输入子路线，映射到原 TODO，不另建完成状态，也不覆盖新的四板主线顺序；
每次只实现一个可归因增量。快速验收优先用 internal 接收/实际应用/斜率对账，
最终精度以示波器实际输出复核。

| 顺序 / 对应任务 | 最小工作 | 正向与反向验证 / 退出条件 |
|---|---|---|
| 输入定位 / `VDC-TIME-002`、`VDC-EVID-001` | 复用当前四板配置和板端记录，核对 reference TX/local RX 时间、有效标志、observer 各阶段计数与实际 accepted/DCO update 增量。 | 从预热开始记录，全部 STOP 后读取；明确实际拒绝分支。普通收发通过但无 DPLL 输入时只报告输入缺口；已有字段足够则不新增诊断功能。 |
| 稳定时间接入 / `VDC-TIME-002/003/004` | 只补已定位的时间来源、同次有效事件关联或交接缺口，经原有准入路径接入。 | 首帧故意无效仍能由后续有效帧开始更新；重复、旧样本、覆盖及 STOP 撤旧拒绝；普通 TDMA 持续。当前四板通过即可向下一步推进，其他容量覆盖保留独立待办。 |
| 单样本跳过 / `VDC-SAMPLE-001` | 分离单次输入拒绝与全局时间基准失效；保持有效控制状态，不清积分。该切片的软件工作可在输入补齐期间独立准备。 | 在已有跟踪状态插入坏帧/缺帧/重复/旧样本，DCO 与积分保持；下个有效输入正常更新；真实 STOP/换代继续撤旧。host 证明分支，实板用原件与输出证明恢复。 |
| 更新步长 / `VDC-SERVO-002` | 实际间隔、Ki 定义及饱和单独收敛；不混入整套 PI 调参。 | 不同有效间隔和回绕下不产生错误频率跳变；首样本不形成伪频率；过长间隔走保持/重捕获策略，实际更新成本入静态预算。 |
| 锁相与恢复 / `VDC-CMD-001/005`、`VDC-LOCK-001`、`VDC-HOLD-001` | 沿既有角色、命令运输及共同生效时间方案接通一主三从；随后用真实输出优化 FLL/PI，并验证持续失效与恢复。 | 板端输入/误差/命令应用与四路输出对账；偶发丢样本不中断输出，连续缺失不能伪造正式锁定。主从命令缺口与本地时间输入分别报告。 |

跨域语义需要冻结时先更新对应 Architecture/registry 并独立审核；本方案不直接开放
隔离的 resident command 功能，也不替代 `VDC_COMMAND_TRANSPORT_PLAN.md`。
每个固件、PIO、工具或测试切片执行相关 host、当前源码 Release、四板 quick P3 和
该功能专项，保留失败后分离提交。本文纯文档调整不重跑硬件验收，不改变既有 P3 结论。

## 5. HAOFV、观测与精度

Core1 TDMA 是物理时序/PIO/DMA 的唯一 owner；Core0 负责准备、解析和记录；Core1
SyncDpllFB 是 PI、DCO 和从机定时应用的唯一实时 owner。跨核继续使用有界、版本化
交接；不在 Core1 进行存储、SCPI、等待或动态分配。局部 DPLL 拒绝不隔离健康 TDMA。
全部静态相位预算仍由 `app_realtime_profile.c` 决定，已有超限继续保留；首帧专项
退出主线不等于时序任务通过，也不妨碍已授权的有界调试继续定位真实输入。

SCPI 仅触发：从首次 START 到所有板 STOP ACK 期间无查询采样。板端 SRAM 保留
预热、错误、有效输入与状态变化，全部 STOP 后顺序保存 SD、读回核验，不离线挑好窗
宣称整个过程无错。TDMA 原生记录覆盖预热；DPLL trace 容量以
`VDC_DPLL_MANAGER_DPLL_CAPTURE_MAX_SAMPLES` 为事实源，按更新写入且满即冻结。
因此在预声明的自主观察阶段用控制命令 ARM trace，STOP 后核对实际覆盖阶段；
零记录或只覆盖 bootstrap 的记录不能当作自主锁相失败，也不据此扩充缓冲。
四板示波器 CH1–CH4 对应 NO1–NO4 的 DPLL 输出，探头 1×，
以 CH1/NO1 上升沿触发；配置为当前夹具快照，非架构常数。

100 ns 为用户提出的相对 NO1 输出精度候选总预算（目标快照，非冻结门限），包含
时间戳误差、有向时延/bias、共同时间映射、servo 残差、DCO 和测量不确定度。
允许有界采样时差，不要求各 PIO 在同一系统时钟周期读取；分辨率不等于准确度。
用实测误差构成决定后续优化优先级，不先以追求启动逐周期完美为锁相前置。
