## 1. 总体产品定位

产品名称统一为 **DTC100 Distributed Trigger**，应用场景统一表述为 **RP1200波导天线测试系统**。

外部主控入口为 A3 节点的 USBTMC / USB488。成品接口不再以 CDC 作为对外业务接口；CDC 只作为 validation 固件或调试固件的维护切换能力。

四板系统按统一硬件、不同角色建模：

| 节点 | 角色 | 核心职责 |
|---|---|---|
| A0 | 扫描/转台/DPLL/ring origin | 捕获位置或 Compare Out，生成 `T_fire_base`，维护扫描编排和虚拟 DC origin |
| A1 | DUT/链路/SP8T | 近端输出 DUT/链路切换触发，捕获 DONE/T2 |
| A2 | 馈源/极化/SP2T | 近端输出馈源/极化触发，捕获 DONE/T2 |
| A3 | 上位机网关/VNA/网分近端节点 | USBTMC/SCPI 接入、VNA 触发与 READY/T2、配置/日志网关 |

核心运行原则：

- 上位机只做配置、启动、停止、状态监控、数据读取和报告生成。
- RUN 态由四板硬件内部自循环，不由上位机逐点推进。
- RJ45_SYNC_RING 传递 SYNC、FIRE_LOAD、DONE、MEAS_DONE、FAULT 和状态，不串行传递业务触发边沿。
- 各节点提前装载预约，PIO 到点输出本地 SMA 边沿。
- 通信抖动只影响是否 late；一旦 PIO 已装载，USB/SCPI/SD/UI 抖动不能进入边沿。

## 3. 硬件与隔离决策回顾

### 3.1 USB / CH343 / RS485

USB、CH343、RS485 属于近端连接，不会有长跨距，但需要接外部设备。

结论：

- USB、CH343、RS485 不需要隔离。
- USB CC 下拉、USB ESD 和 USB 连接器信号参考应接本地域 GND。
- USB 连接器外壳不建议直接当作隔离 GND；外壳/屏蔽应按机壳地/FGND/EMI 策略处理，必要时通过受控 RC/Y 电容/0R/DNP 单点耦合。
- ESD 器件应把浪涌回流引到对应接口参考地或机壳/FGND路径，避免把外部冲击直接打进 MCU 数字地。

### 3.2 RS422 / BiSS / Trigger

有部分接口需要隔离，特别是 RS422/BiSS/Trigger 线缆侧。

结论：

- RS422 需要隔离。
- BiSS/RS422/Trigger 线缆侧按 FGND/隔离域处理。
- ISO1452 控制类接口必须有明确默认态：复位和 bootloader 阶段驱动关闭，初始化完成后才使能。
- DE 下拉、`/RE` 默认接收，避免上电误驱动或总线冲突。

### 3.3 GND / FGND / 地桥

为了防止 GND 分割导致的问题，可以预留 0R 或电容位置，在调试时决定是否连接 GND 和 FGND。

结论：

- GND-FGND 只允许受控单点策略。
- 可预留 0R/DNP 或小电容作为 EMI 调试件。
- 量产隔离默认 DNP 或按 EMC 验证结果装配。
- 多点直流跨接会破坏隔离边界，并引入不可控地环路。

### 3.4 PIO 输入输出 22R 串阻

PIO 输出侧 22R 串阻用于抑制边沿振铃、降低过冲和 EMI。

结论：

- 输出串阻优先放在驱动源端，也就是 MCU/驱动器端。
- 输入侧如果需要限流/保护，可靠近接口端，但这和输出源端阻尼不是同一目的。
- 22R 可以跑 50MHz，关键不是 DC 频率，而是边沿速度、走线长度、负载电容和阻抗不连续。
- 对高速边沿，串阻与驱动内阻共同形成源端匹配，减少反射。
- 实际阻值可在 0R/10R/22R/33R 间通过示波器和 EMC 结果调整。

### 3.5 12V / 电子保险丝 / ESD

电子保险丝前端已经有一定浪涌/限流保护，但不等同于接口 ESD/浪涌钳位。

结论：

- 外部 12V 入口仍建议在连接器附近放 TVS。
- SMBJ18A 可用于 12V 入口的单向 TVS 候选，但需要结合正常电压范围、浪涌等级和后级器件绝对最大值确认。
- TVS 位置应靠近入口和回流路径，避免浪涌电流穿过敏感地。

## 4. 外部电流测量决策回顾

### 4.1 INA180 / AMC1301 / 隔离问题

最初讨论 U24 为 INA180A2IDBVR，用于测试外部电流，但存在跨隔离边界问题。

讨论过的方案：

- INA180 后端跨隔离边界直接接 MCU ADC。
- 用光耦隔离模拟量。
- 用隔离 ADC。
- 用隔离放大器，例如 AMC1301。
- 后端接 LED，仅通过亮度判断。
- 测内部 5V 电流，避免跨域。
- 继续测 12V，但用变压器/隔离供电。

最终阶段性结论：

- 如果测外部 12V 且信号跨隔离边界，INA180 直接跨域会破坏隔离。
- AMC1301/隔离放大器是隔离测量的正确方向，但封装和外围面积较大。
- 用户后来倾向“只判断模块数量，不做精密测量”，并考虑测 12V 供电链路电流。
- 如果最终只判断模块数量，测量精度要求降低，重点是分辨不同模块数量下的电流阶梯。

### 4.2 分流电阻与量程

讨论过 50mR 和 20mR。

约束：

- 最大电流约 2A。
- 如果有四个分布式板卡，供电链路上可能有多个采样电阻串联。
- 50mR x 4 在 2A 时会带来 0.4V 压降，偏大。
- 20mR 更合理，2A 时单个压降约 40mV，四块总压降约 160mV。

结论：

- 当前产品化倾向使用 20mR。
- 只做模块数量判断时，可以通过平均、阈值和迟滞抵抗 ADC 底噪。
- 需要在固件中保留基线测量和水位统计，不做精密电流表承诺。

## 6. RTOS + 双核架构决策回顾

### 6.1 总体模型

用户要求产品化需要 RTOS + 双核：

- 一个实时核。
- 一个控制核。
- core1 跑状态机/实时逻辑。
- 在 DEMO 板先完成基础工作，再逐步加回完整状态机。

最终架构模型：

```text
core0 FreeRTOS 控制核
core1 realtime 裸实时循环 / 状态机
```

core0 承担：

- USB device / USBTMC / CDC validation
- SCPI 解析
- A3 网关
- A0 loop engine
- VDC sync
- DPLL
- refmem sync
- storage
- OTA
- UI
- diag

core1 承担：

- TriggerAO 快路径
- PIO 装载
- local_fire
- capture/T2
- RJ45 帧首沿服务
- late/CRC/fault 快速判定

### 6.2 RTOS 任务划分

关键任务：

### 6.3 heap / 栈策略

用户提出先把 RTOS heap 加大，先大后小，逐步测水位。

结论：

- heap 先给 128KB。
- 通过 `SYSTem:RTOS:STATus?` / `SYST:RTOS:STAT?` 读取 heap 和任务栈水位。
- 后续按实际水位收缩栈和 heap。
- `io_frontend` 承载过多功能，需要拆分任务，而不是继续堆栈。

### 6.4 工具和验证策略

用户明确要求每一小步代码修改都需要烧录验证，避免问题积累。

验证策略：

- 每个小步修改后构建、烧录、查询。
- 固化有用的小工具。
- 每个脚本都要管理串口生命周期，避免串口未关闭导致通信失败。
- 可用 `tools` 中工具下载验证。

## 7. USB / CDC / USBTMC 调试回顾

调试过程中曾从 USBTMC 切回 CDC 验证。

现象：

- ssCOM 可以正常通信。
- `*IDN?` 返回 `GTS,DTC100,73E940D75B406BCD,0.1.0`。
- `SYST:CORE?` 能查询 core1/core0 心跳。
- `TRIG:MODE 1` 和 `TRIG:ARM` 一度导致卡死。
- LCD 也会卡住，说明不是单纯 USB 响应问题，而是系统路径被阻塞。

定位过程：

- 增加状态/调试查询。
- `SYST:TRIG:DBG?` 曾返回调试字段。
- 看到 `TRIG:MODE 1` 后能返回 `"OK"`，后续状态显示进入 `SEQ_STEP`，说明卡死点不是完全在命令解析入口。
- 继续判断任务划分过粗、`io_frontend` 承载过多工作。

结论：

- USB device 任务必须保持活性，不能被业务状态机或 SD/UI/日志阻塞。
- SCPI 任务只解析和投递事件，不直接跑重业务。
- core1 和 core0 交互要使用通用、清晰的命令队列/状态 ring/快照机制。

## 8. 反射内存 / 分布式向量表回顾

用户强调：

- 分布式模块最好维护同一块向量表。
- PinProbe A1 有 RamVector 历史方案可参考。
- PinProbe 的表只有 2KB。
- RP2350 这里 64KB 表足够列出 8 个节点。
- 后续可能增加模型节点、模拟网分、模拟转台。

结论：

- 使用完整 64KB DistributedVectorTable，避免后续协议扩容破坏上位机和日志格式。
- 真实板卡和模型节点都占用统一 node slot。
- 反射内存不是精确触发通道，不能替代 PIO 本地装载。
- 反射内存只同步小 delta，不传大文件、波形、OTA payload 或 SD 内容。
- 日志解释历史，反射内存保存当前事实和摘要。

关键原则：

```text
命令是意图
镜像是事实
状态是推导
日志是解释
```

核心区域包括：

- Header/Directory
- SystemSlot
- Role/ConfigSlot
- VdcSlot
- LoopSlot
- DpllSlot
- NodeSlot[8]
- TriggerSlot[8]
- IoSlot[8]
- CalibrationSlot
- StatisticsSlot
- AckCommandSlot
- FaultEvidenceSlot
- GatewaySlot
- OtaStorageUiSlot
- TlvExtension

## 9. 触发业务与序列配置回顾

用户明确要求业务配置指令分层：

- 业务配置都是 `CONFigure`
- 查询都是 `READ`
- 系统指令仍为 `SYSTem`
- 动作执行由 `TRIGger` / `CALibration` / `SYNC` 负责

### 9.1 触发参数

`CONFigure:TRIGger` 参数顺序定为：

```text
chan_cnt,pol,freq_cnt,wave_cnt
```

展开顺序定为：

```text
通道 -> 极化 -> 频点 -> 波位
```

极化编码：

| 值 | 含义 |
|---:|---|
| 0 | H |
| 1 | V |
| 2 | BOTH |

示例：

```text
5 个频点 x 8 个通道 x 1 个波位 x 双极化 = 80 个状态
```

### 9.2 序列配置

早期的 `CONFigure:SEQuence <plan_id>,<state1>,<state2>,...` 不够产品化。

结论：

- 使用 `CONFigure:SEQuence <plan_id>,#<block>`。
- block 内是固定结构数组。
- 每条记录必须明确映射到 SWITCH1/SWITCH2/pol/freq/wave。

记录字段：

```text
state_id,
switch1,
switch2,
pol,
freq_index,
wave_index,
dwell_us,
flags
```

### 9.3 SWITCH 指令

用户要求：

- SP8T-SWITch1，SP2T-SWITch2。
- 合成一条指令，用 `SWITch#` 区分开关。
- SWITCH 说明放在运行控制/业务控制相关页面。

结论：

```scpi
CONFigure:SWITch# <value>
READ:SWITch#?
```

其中：

- `#=1`：SWITCH1 / SP8T，值 1..8。
- `#=2`：SWITCH2 / SP2T，值 0/1。

## 10. 角度扫描与断点序测回顾

用户澄清：

- 断点序测不是测试序列本身。
- 断点是运动上的角度断点。
- 测试序列是每个角度上跑的序列。
- 扫描角度 + 断点序列位置 + 测试序列，可以实现断点序测功能。
- 断点内部的序列会全部测一遍。

结论：

```scpi
CONFigure:ANGLe:SWEEP <start_deg>,<stop_deg>,<step_deg>
CONFigure:ANGLe:BP <angle_deg>
CONFigure:ANGLe:BP:CLEAr
READ:ANGLe:BP?
READ:ANGLe:POSition?
```

关键语义：

- `CONFigure:ANGLe:SWEEP` 是扫描角度，不是断点。
- `CONFigure:ANGLe:BP` 是角度断点。
- 断点在角度点开始前判断。
- 命中断点后暂停，该角度点内部测试序列尚未输出。
- `TRIGger:CONTinue` 从该角度继续，并完整跑完该角度点内测试序列。

## 12. 校准功能回顾

### 12.1 校准本质

用户纠正：

> 校准是非常快的，只是计算线缆的延时。

因此之前“长任务、STOP/ABORt”的评审结论被修正。

最终结论：

- 校准是快速短事务。
- `CALibration:STARt` 响应前完成计算。
- 不设计复杂停止/取消流程。
- 一次只允许一个 `CAL BUSY` 事务。
- 失败不覆盖旧 staging 数据。
- 结果先进入 staging，再保存、激活。

校准流程：

```text
配置链路
-> 快速测 delay
-> 写入 staging
-> 读取结果
-> 保存版本
-> 激活版本
-> SYNC 使用 active 表
```

### 12.2 校准链路与参数

核心指令：

```scpi
CONFigure:CAL:LINK:ADD
CONFigure:CAL:LINK:SET
CONFigure:CAL:LINK:DELete
READ:CAL:LINK?

CONFigure:CAL:PARameter:ADD
CONFigure:CAL:PARameter:SET
CONFigure:CAL:PARameter:DELete
READ:CAL:PARameter?

CALibration:STARt
READ:CAL:STATe?
READ:CAL:RESult?
```

校准对象：

| 对象 | 含义 |
|---|---|
| `SMA` | 节点间 SMA 输入/输出触发链路 delay，例如 A0 OUT1 到 A1 IN1 |
| `NODE` | RJ45_SYNC_RING 节点间触发回传链路 delay |
| `DEVICE` | SP8T、SP2T、VNA READY、设备完成 T2 等动作延迟 |
| `TEMP` | 节点温漂和慢变补偿参数 |

### 12.3 校准追溯

为了满足出厂、现场复测、报告归档，需要追溯字段。

新增：

```scpi
CONFigure:CAL:META <cal_id>,<operator>,<fixture_id>,<cable_id>,<temperature_c>,<note>
READ:CAL:META? [cal_id]
```

追溯字段至少包括：

```text
source,
cal_id,
timestamp,

```

### 12.4 校准版本和质量

核心指令：


规则：

- 所有 `CONFigure:CAL:*` 写 staging。
- `CALibration:ACTivate` 才切换 active。
- SYNC 和 TRIG 只读取 active。
- TRIG RUN 中禁止校准表增删改、保存、激活和回滚。

## 13. 同步功能回顾

### 13.1 同步基于校准

用户明确：

- 同步是基于校准的。
- 校准会把每个节点之间互联的触发脉冲链路 delay 测算出来。
- 同步用于验证和开启/维护 DPLL 和 DC 时钟。

结论：

- 同步域不重新测 delay。
- 同步域只消费 active 校准表。
- 本地晶振和 `local_tick` 先存在；BiSS-C/RJ45 组网提供跨节点边沿观测；DPLL 基于观测收敛出虚拟 DC。
- `LOCKING` 前的 DC 只能作为 provisional/free-run 估计，不能作为正式触发运行或 T2/DEVICE 校准时间基准。
- `CONFigure:SYNC:*` 写 staging。
- `SYNC:SAVE` 保存同步配置包。
- `SYNC:ACTivate` 切换 active。
- `SYNC:STARt` 只使用 active。

### 13.2 RJ45_SYNC_RING 拓扑

技术报告同步口径：

```text
A0 -> A1 -> A2 -> A3 -> A0
```

结论：

- `CONFigure:SYNC:RING` 中的 `node_order` 展开的每一跳，都必须存在同方向 NODE 校准链路。
- 必需链路必须满足 `enabled=1`、`required=1`、`data_state=VALID`。
- A0->A1 和 A1->A0 不能混用。
- `SYNC:CHECk` 必须输出 `direction_mismatch` 字段，帮助上位机定位方向错误。

### 13.3 同步配置和动作

核心指令：

```scpi
CONFigure:SYNC:CAL
CONFigure:SYNC:RING
CONFigure:SYNC:DPLL
CONFigure:SYNC:GATE

SYNC:CHECk [ACTive|STAGing]
SYNC:STARt
SYNC:STOP
SYNC:RELock
SYNC:HOLDover
```

`SYNC:CHECk STAGing` 只用于离线预检。正式启动流程必须是：

```scpi
CONFigure:SYNC:CAL FIELD_20260811,3A91C027,86400
CONFigure:SYNC:RING A0,A0>A1>A2>A3>A0,1000,12500000,20,0
CONFigure:SYNC:DPLL 300,100,200,1000,LOW_JITTER
CONFigure:SYNC:GATE 1,50,100,0
SYNC:CHECk STAGing
SYNC:SAVE FIELD_SYNC_20260811
SYNC:ACTivate FIELD_SYNC_20260811
SYNC:CHECk
SYNC:STARt
```

### 13.4 同步状态

同步状态：

| 状态 | 含义 |
|---|---|
| `IDLE` | 未启动同步或已停止 |
| `CHECKED` | active 配置和拓扑校验通过 |
| `LOCKING` | 正在估计 offset/rate |
| `LOCKED` | 虚拟 DC 已锁定且满足门禁 |
| `HOLDOVER` | 短时失去同步帧 |
| `FAULT` | CRC、seq、链路时效或 e_vdc 超限 |

HOLDOVER 首版策略：

- 保守。
- 只允许已装载队列完成。
- 不允许新增业务预约。
- 保留日志等待重锁或停止。

## 14. DPLL 决策回顾

### 14.1 两类 DPLL 必须区分

| 名称 | 所属域 | 作用 | 指标 |
|---|---|---|---|
| `SYNC:DPLL` | 同步域 | 虚拟 DC offset/rate 环路 | `e_vdc` |
| 角度预测 DPLL | 触发/扫描域 | 转台角度到未来触发时间预测 | `e_pll` |

结论：

- `SYNC:DPLL` 只表示虚拟 DC 的 offset/rate 同步环路。
- `SYNC:DPLL` 不产生物理时钟，也不替代本地晶振；它把各节点 `local_tick`
  映射到共同虚拟 DC。
- 角度预测 DPLL 属于扫描/触发域。
- 两者指标不能混用。

### 14.2 虚拟环路滤波器

用户提问：

- DPLL 是否需要虚拟环路滤波器？
- 是否需要通过调节虚拟环路滤波器保证稳定？
- 环路滤波器是否有传递函数？
- 是否能通过调节传递函数参数调节？
- 不需要上位机调节，只暴露调试接口。

结论：

- DPLL 需要虚拟环路滤波器。
- 固件内置产品 profile。
- 上位机业务界面只选择 profile。
- 维护接口暴露带宽、阻尼或离散 PI 系数，方便联调和长稳测试。
- 调试覆盖为易失态，不写入出厂默认 profile。

维护指令：

```scpi
SYSTem:SYNC:DPLL:TUNE <bandwidth_hz>,<damping>,<max_slew_ppm>
SYSTem:SYNC:DPLL:COEFficient <kp_q31>,<ki_q31>,<max_slew_ppm>
SYSTem:SYNC:DPLL:OVERRide?
SYSTem:SYNC:DPLL:COEFficient?
SYSTem:SYNC:DPLL:DEFAult
```

调试范围：

```text
bandwidth_hz = 0.01 .. 20
damping      = 0.3  .. 2.0
max_slew_ppm = 1    .. 200
```

运行边界：

- 只允许在 `IDLE`、`STOPPED`、`LOCKING` 使用。
- 正式 `TRIG RUN` 禁止修改。
- 重启或 `SYSTem:SYNC:DPLL:DEFAult` 清除覆盖。

## 18. 当前关键约束总表

| 约束 | 当前结论 |
|---|---|
| 成品外部接口 | USBTMC / USB488 |
| CDC | validation 维护，不作为成品业务接口 |
| 文档源 | Markdown |
| HTML/PDF | 从 Markdown 派生 |
| 校准 | 快速短事务，只计算线缆/链路 delay |
| 校准写入 | staging，保存并激活后进入 active |
| 同步 | 基于 active 校准表，不重新测 delay |
| RJ45 ring | A0 -> A1 -> A2 -> A3 -> A0 |
| HOLDOVER | 只完成已装载队列，不新增预约 |
| DPLL | 同步 DPLL 和角度 DPLL 分离 |
| 上位机 | 不参与 RUN 态逐点实时决策 |
| 反射内存 | 64KB 完整表，8 节点预留，只同步小 delta |
| RTOS heap | 先用 128KB，后续按水位收缩 |
| core1 | 实时状态机/PIO/捕获/late 快路径 |
| core0 | FreeRTOS 控制、USB、SCPI、网关、存储、UI、OTA |
| USB/CH343/RS485 | 近端无需隔离 |
| RS422/BiSS/Trigger | 需要隔离或线缆侧隔离策略 |
| GND/FGND | 受控单点 0R/DNP/电容策略 |
| 电流检测 | 倾向只判断模块数量，20mR 更合理 |
