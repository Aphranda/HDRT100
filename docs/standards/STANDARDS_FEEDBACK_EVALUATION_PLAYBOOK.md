## 0. 适用范围

本手册定义 `docs/standards/` 的**反馈入口、分诊、处置、回流和评估记录**机制。

它只固化“怎么收、怎么判、怎么改、怎么复盘”，不把未发生的外部反馈写成已验证事实。  
外部试点本身属于 G3；本手册为 G3 提供记录入口。

## 1. 反馈来源

| 来源 | 典型输入 | 记录人 |
|---|---|---|
| 外部采用者 | 采用指南看不懂、模板填不下去、裁剪失败 | 域 owner |
| 项目内部 | 反向评估、审计发现、里程碑复盘 | 项目负责人 |
| 标准使用者 | 版本冲突、链接失效、示例过时 | 作者/复核者 |
| 事故/返工复盘 | 因治理缺失导致的返工、证据不可复跑 | 复盘主持人 |

规则：

- 每条反馈有稳定 ID、来源、类型、问题、严重度、处置、回流任务和状态。
- 外部反馈必须由外部采用者确认，不能由本域代填。
- 未处置的反馈不能写成 `CLOSED`；延后必须有复验判据和闭环里程碑。
- 反馈日志只追加，不覆盖历史。

## 3. 分诊与处置

| 严重度 | 判据 | 处置时限 | 处置方式 |
|---|---|---|---|
| 高 | 标准不可执行、导致错误决策、违反安全/法规、阻断采用 | 下一次复审前 | 立即修标准或加临时补丁，升 PATCH/MINOR |
| 中 | 模板难用、示例过时、边界不清、需要额外解释 | 一个季度内 | 排入下个 MINOR |
| 低 | 措辞、链接、排版、非阻塞建议 | 下一次 PATCH | 批量处理 |

处置选项：

- `接受`：修改标准/模板，回流 TODO；
- `拒绝`：写明理由和适用边界；
- `延后`：写复验判据和闭环里程碑；
- `转外部`：属于采用方项目自身问题，提供指导但不改标准。

## 4. 回流规则

1. 反馈 → 日志条目；
2. 分诊 → 严重度/owner/处置；
3. 修改 → 标准/模板/指南，升版本（按版本手册）；
4. 验证 → docs 门禁 + 采用方复测；
5. 关闭 → 写证据和关闭日期；
6. 复盘 → 每季度汇总一次，删除无效反馈模板。

回流目标只能是：

- 本域标准/模板/指南；
- 项目治理计划（G2/G3/G4）；
- 采用方自己的本地化文档。

不得把外部反馈直接写成产品契约；需要契约化的，回到项目 `DOCS_REGISTRY.md` 流程。

## 6. 评估方法

1. 固定维度（六系统 + 协作/认知）；
2. 每维 1–4 分，给证据和缺口；
3. 采样命令和文件，不凭记忆；
4. 结论区分“事实 / 判断 / 建议”；
5. 评估记录写入本手册或受控报告，不留在聊天；
6. 每次评估至少保留 3 条可执行改进项。

## 7. 度量

| 指标 | 口径 | 目标 |
|---|---|---|
| 反馈响应时间 | 从记录到首次处置 | 高 ≤7 天，中 ≤30 天 |
| 反馈关闭率 | `CLOSED` / 总反馈 | ≥80% |
| 外部反馈数 | 真实外部条目 | ≥3（G3 后） |
| 回流完成率 | 已回流任务 / 接受反馈 | 100% |
| 评估按时率 | 按时评估 / 应评估 | 100% |
