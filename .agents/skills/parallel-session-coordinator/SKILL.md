# 并行会话协调 Agent

> 本 skill 只定义"协调者"这一个角色的增量职责。仓库硬规则、门禁命令、lane 划分仍以
> `AGENTS.md`、`docs/check/` 和 `.agents/skills/hdr100-project-collaboration/SKILL.md` 为准；
> 有冲突时以它们为准，并回来修本文件。

## 什么时候用

用户明确让本会话"做协调者 / 调度 / 监督其他并行会话"时启用。**不是**每个会话都该做的事。
本会话一旦进入该角色，默认**只读监督**，不接手任何 worker 的代码或文档任务。

## 每轮固定动作（顺序不能省）

1. 读 `.agents/coord/` 下所有 `*.md`（简报），排除 `coordinator.md` 自己。
2. 读 `.agents/coord/coordinator.md` 的"上一轮"段落，确认上轮指令是否被执行。
3. 需要细节时用 `session_search` / `session_event_read` 按 lane 关键词查对应会话的最近事件；
   **不要**整篇读日志，只读最近 N 条与关键决策。
4. 跑只读命令取证：`git status --porcelain`、`git diff --stat`、必要的门禁输出。
   注意：共享工作区只有一个 index，`git status` **不能**归因到某个会话，不能据此断言"X 改了 Y"。
5. 按下面的检查表判定每个会话状态，写回 `.agents/coord/coordinator.md`。

## 漂移检查表（发现即标记，不猜）

| 检查 | 怎么判 | 标记 |
|---|---|---|
| 目标漂移 | 简报声明的目标 vs 最近工具调用/编辑路径 | `drift` |
| 越界 | 改动路径不在其声明的 lane（docs / tools / firmware）内且未说明 | `out-of-lane` |
| 重复劳动 | 两个会话声明同一目标或同一批文件 | `dup` |
| 证据缺失 | 声称完成/`✅`，但没有可复跑命令、receipt 或指纹 | `no-evidence` |
| 违规完成 | `pending`/未验证写成完成（§8 红线） | `false-done` |
| 停滞 | 简报超过 30 分钟未更新且无进展；或同一步反复失败 ≥3 次 | `stuck` |
| 积压 | `git status --porcelain` 条目接近/超过 40（共享口径） | `backlog` |
| 冲突风险 | 两个会话声明同一文件/同一目录，且都没说先后顺序 | `overlap` |

判定不确定时写 `hypothesis`，不要写成结论。

## 输出格式（`.agents/coord/coordinator.md`）

```
更新时间: <YYYY-MM-DD HH:mm>
总览: <一句话：几路在跑、几路正常、几路要干预>

## 状态
| 会话(lane) | 状态 | 依据(文件/命令/事件) | 指令 |
|---|---|---|---|
| refmem-entry | ok | 简报 14:20，门禁已跑 | 继续 |
| docs-check | drift | 声明只改 docs/，实际动了 tests/ | 见下 D1 |

## 给各会话的指令
- D1 -> docs-check: <具体动作，含文件/命令，1-3 条，可执行>

## 需要用户裁决
- <≤3 条，没有就写"无">
```

## 向用户汇报（每轮必做，不能只写文件）

汇报是给用户的**结论**，不是把看板贴一遍。固定格式、≤10 行、每路一行、必须带依据：

```
并行工作汇报 <YYYY-MM-DD HH:mm>
总览: <N 路在跑 / a 正常 / b 需干预 / c 卡住>
- <lane> [正常|漂移|越界|重复|卡住|无证据] <一句话现状 + 依据>
- ...
风险: <跨会话的重叠/积压/门禁风险；无则写"无">
需要你裁决: <≤3 条；无则写"无">
建议下一轮: <时间或触发条件>
```

硬规则：
- 每路状态必须能从简报或 `session_event_read` 里指出依据；说不清就写 `hypothesis`。
- 不写 `✅`，不写"应该没问题"；未验证就写"未验证"。
- 汇报同时落盘到 `.agents/coord/report.md`（覆盖上一轮），方便用户不回翻聊天记录。
- 没有变化也要汇报"无变化 + 时间戳"，不要静默。

## 边界（写清楚，避免协调者自己跑偏）

- **不改** worker lane 内的代码/文档；需要改时写指令让 worker 改，或经用户同意后接手并说明原因。
- **不写 `✅`**：门禁结果只做汇总，完成结论由对应 worker 或用户给。
- **不重复**已有 worker 的工作；发现重复只做仲裁建议（谁继续、谁停）。
- **没有锁**：协调者不能阻止写入，只能"发现—指令—复查"。纠正延迟取决于 worker 何时重读本文件。
- 每轮结束时如果无事发生，也必须写"无变化 + 时间戳"，让看板可信。
